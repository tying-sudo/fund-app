# AI 平台迁移检查清单

## 导入前

- [ ] 确认私有 Git 仓库、基线提交、分支状态和未提交补丁的应用顺序。
- [ ] 保留 `docs/WORKLOG.md`，并在交接说明中标明未完成事项和生产验证状态。
- [ ] 扫描补丁、`server/`、`scripts/`、Android 配置与部署文件中的密钥；轮换旧平台可能接触过的凭据。
- [ ] 排除 `.env*`、`server/data/`、缓存、日志、用户数据、数据库/Redis 备份、APK、签名材料和 SSH 凭据。
- [ ] 验证前端、Node 服务和网格服务可各自构建/测试，而不连接生产环境。

## 新平台权限

- [ ] 默认仅授予仓库读取、分支/PR 和受限 CI 权限。
- [ ] 生产服务器、数据库、DNS/CDN、发布密钥和 Android 签名使用独立 Secret，默认不授予写权限。
- [ ] 首次任务只做架构审计和本地验证；生产部署必须由单独授权触发。

## 发布前

- [ ] 前端调用与后端路由、认证、限流、超时和错误契约已核对。
- [ ] 数据库迁移是追加式、具备兼容与回滚方案，未修改已部署迁移。
- [ ] 网格服务的测试从 `vendor/valuation_grid` 目录执行，未覆盖本地集成定制。
- [ ] Android 发布前重新核对版本名、versionCode、签名、`/api/app/version` 和 APK 下载哈希。
- [ ] 对外发布后从公网验证页面、核心 API、网格健康状态和 APK 字节/哈希；本地测试或 SSH 成功不足以证明发布完成。
